# Memex v1.2.2

本次更新让 AI 客户端可以修改任务，并修复周报生成在部分网关下的解析失败。

## 新增

- MCP 新增 `update_task` 工具，可修改任务的状态、优先级、截止时间、标题、描述和标签
- 设置中新增「允许 AI 修改任务」开关，默认关闭，与其他布尔设置共用同一控件样式
- `update_task` 返回更新后的任务和本次实际改动的字段列表
- 截止时间支持 ISO 8601 字符串、毫秒时间戳和 `null`（清除）
- 外部写入后应用在重新获得焦点时自动刷新，避免界面显示过期数据

## 安全与隐私

- 写入开关默认关闭，且关闭时 `update_task` 不出现在工具列表中，客户端无法据此推断服务端能力
- 每次调用实时读取开关状态，无缓存，关闭后立即生效
- 已软删除的任务一律按不存在处理，回收站数据不可被修改
- 写入复用应用本体的 `TaskRepository.update`，`status` 与 `completedAt` 的联动逻辑只有一份实现
- MCP 与 Electron 应用通过 WAL 并发访问同一数据库，冲突时返回 `DB_LOCKED` 而非崩溃

## 修复

- 修复部分 OpenAI 兼容网关把标准响应包在 `data` 字段中时，周报生成报「模型返回内容格式无效」的问题
- 修复网关只返回推理过程、正文为空时，错误信息无法区分「格式错误」与「推理占满输出」的问题
- 兼容旧式 `choices[0].text` 返回形式
- 修复超出 JavaScript `Date` 可表示范围的截止时间会写入数据库、并导致后续 `list_tasks` 整体失败的问题
- 修复设置界面的开关按钮缺少可访问名称的问题（同时惠及原有的三个桌面行为开关）

## 数据兼容

- 新增 `mcp_task_write` 设置项，默认 `false`
- 不修改或删除现有任务、笔记、标签和设置
- 已有数据库升级后该设置项缺失时按默认值 `false` 处理，UI 与 MCP 侧行为一致
